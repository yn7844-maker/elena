# 오늘의 뉴스

로그인·비밀번호 없이 사용하는 뉴스 대시보드입니다. 즐겨찾기·메모는 각자의 브라우저에 개인 저장됩니다. 금융·경제·AI·사회·문화·기타 기사, 원문 링크, 개인 즐겨찾기·메모, 제목 주요 단어·급상승 단어, 네이버 검색어 트렌드를 제공합니다.

## 구조

```text
GitHub Actions (한국 시간 07:00 / 08:00 / 09:00 / 10:00 / 11:00 / 15:00 / 18:00 / 21:00 수집 시작 예정)
  → NAVER API HUB 뉴스 + 검색어 트렌드
  → Neon PostgreSQL에 저장
  → Vercel의 공개 조회 API → 대시보드 (개인 메모·즐겨찾기는 브라우저 저장)
```

Vercel에서는 서버 파일에 데이터를 저장하지 않습니다. 별도 PostgreSQL이 필요합니다. DB는 Neon을 권장하며 Vercel과 같은 DB를 GitHub 수집 작업에서도 사용합니다. 저장소를 비공개로 바꾸어도 웹사이트가 자동으로 비공개가 되는 것은 아닙니다. 기사·제목 키워드·검색 트렌드는 로그인 없이 조회됩니다. 즐겨찾기·메모는 localStorage의 `elena.personal.v1`에 기사 URL을 기준으로 저장됩니다. 서버는 조회 전용이며 로그인·공유 메모 수정 API는 제공하지 않습니다. 사이트 주소를 아는 사람은 누구나 기사를 볼 수 있지만 각 브라우저의 개인 메모는 서버에 전송되지 않습니다.

## 1. 데이터베이스 준비

1. https://neon.com 에서 프로젝트를 생성합니다. 초기에는 무료 플랜을 검토하세요.
2. **Connect**에서 `postgresql://...`로 시작하는 **pooled connection string**을 복사합니다. `sslmode=require` 등 제공된 SSL 설정을 유지하세요.
3. 이 값을 아래 GitHub와 Vercel 양쪽의 `DATABASE_URL`로 입력합니다. 연결 문자열에는 비밀번호가 포함되므로 코드에 적지 않습니다.

테이블은 최초 수집/접속 시 자동 생성됩니다. DB 역할에는 테이블 생성 권한이 필요합니다. 무료 플랜의 용량·사용량 제한과 요금은 신청 화면에서 확인하세요.

## 2. 네이버 API 입력 위치 — GitHub Secrets

저장소 → **Settings → Secrets and variables → Actions → New repository secret**에서 아래 5개를 등록합니다.

| Secret 이름 | 넣을 값 |
|---|---|
| `DATABASE_URL` | 위 Neon DB 연결 문자열 |
| `NAVER_NEWS_CLIENT_ID` | API HUB **뉴스** Application의 Client ID |
| `NAVER_NEWS_CLIENT_SECRET` | API HUB **뉴스** Application의 Client Secret |
| `NAVER_TREND_CLIENT_ID` | API HUB **검색어 트렌드** Application의 Client ID |
| `NAVER_TREND_CLIENT_SECRET` | API HUB **검색어 트렌드** Application의 Client Secret |

API HUB 인증은 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY` 헤더를 사용합니다. 서로 다른 Application이면 서로 다른 키를 입력합니다. 같은 키로 두 API를 사용할 권한이 있다면 같은 값을 각각 등록해도 됩니다. 일반 NCP 계정용 Access Key/Secret Key와 혼동하지 마세요.

이 구조에서 네이버 키는 **Vercel에 입력할 필요가 없습니다.** 수집은 GitHub Actions에서만 실행하고 Vercel은 저장된 DB를 읽습니다. 키를 프런트엔드, README, Git 커밋, `NEXT_PUBLIC_` 또는 `VITE_` 변수에 넣지 마세요.

## 3. 첫 수집 실행

1. GitHub **Actions → Collect news → Run workflow**를 클릭합니다.
2. 워크플로가 비활성화되어 있으면 먼저 활성화합니다.
3. 녹색 완료를 확인합니다. 오류가 나면 해당 작업의 마지막 로그를 확인하세요.
4. 이후 기본 브랜치에서 한국 시간 **07:00 / 08:00 / 09:00 / 10:00 / 11:00 / 15:00 / 18:00 / 21:00**에 하루 8회 예약 실행됩니다. GitHub 예약 작업은 지연·누락될 수 있으며 정시 실행을 보장하지 않습니다. 공개 저장소는 60일간 활동이 없으면 예약이 비활성화될 수 있습니다. 비공개 저장소는 Actions 사용 시간에 따라 요금/한도가 적용될 수 있습니다.

### 예약 지연 시에도 수집 유지

예약표는 UTC `0 0,1,2,6,9,12,22,23 * * *`로 위 한국 시간에 대응합니다. 수집 직전에 실제 한국 시각을 로그에 남기고, 정각보다 5분 넘게 지연되면 경고합니다. **5분은 경고 기준일 뿐이며 지연 때문에 작업을 중단하거나 회차를 버리지 않습니다.** 오전 00:39 같은 시각에 늦게 도착해도 수집합니다. 과거의 5분 초과 중단 규칙은 제거되었습니다.

화면의 **최근 수집 완료**는 예정 시각이 아니라 실제 완료 시각입니다. 수집 실패 시 다음 실행은 최근 완료 기준 48시간을 겹쳐 조회하여 보완합니다. 검색어별 페이지·호출량 제한 때문에 누락의 완전 복구를 보장하지는 않습니다. GitHub Actions의 실행 지연이나 예약 자체의 누락은 이 코드가 없앨 수 없습니다.

뉴스 수집은 기초 검색어 25개를 출발점으로 자동 확장합니다. `lib/config.mjs`의 주제별 연관어 풀에서 실행마다 3개씩 순환 선택하고, 최근 7일간 주제별 최신 최대 800건의 기사에서 새로운 표현을 찾습니다. 후보는 URL 기준 3건 이상, 서로 다른 사이트 2개 이상에서 나타나고 기사 문맥에 주제 단어가 있어야 합니다. 발견한 표현은 확인된 주제 단어와 묶어 검색하며, 주제당 최대 2개를 추가합니다.

기초 검색은 검색어당 최대 5페이지(500개), 연관·자동 발견 검색은 최대 2페이지(200개)입니다. 주제당 연관 3개·자동 발견 최대 2개이므로 현재 설정의 기본 최대 뉴스 요청은 실행당 185회이며, 재시도를 포함한 실제 뉴스 HTTP 요청은 200회로 제한합니다. 실행 시간은 20분 이내에서 다음 조회 시작을 제한하고 마무리합니다. 검색어 전체를 무제한으로 따라가지 않습니다. 검색 계획은 실행 이력에 저장하고 대시보드 아래 **수집 상태 및 데이터 기준 → 이번 수집에 사용한 검색어**와 GitHub 로그에서 확인할 수 있습니다.

네이버가 제공하는 연관 검색어 목록이나 의미 검색 API를 호출하는 기능은 아닙니다. 규칙과 기사 동시 출현을 이용한 확장으로 관련 기사 전체의 수집을 보장하지 않습니다. 별도 AI API 키는 필요하지 않습니다. 트렌드는 기존과 같이 어제까지 최근 30일, 고정 5개 그룹을 한 요청으로 비교합니다.

## 무료 외부 예약 서비스 연결 (선택)

cron-job.org가 GitHub의 workflow_dispatch API를 호출하도록 연결할 수 있습니다. [가입·토큰·예약 설정·연결 확인·기존 예약 전환 안내](docs/external-scheduler.md)를 따르세요. 외부 요청도 지연 시 경고만 남기고 수집을 계속합니다. GitHub 실행 대기는 남으므로 정각을 보장하지 않습니다. **기본 GitHub 예약은 계속 유지합니다.** `COLLECTION_SCHEDULER` 변수로 예약을 끄던 기능은 제거했습니다. 이미 등록했다면 삭제해도 됩니다. 외부 예약이 실제로 실행되는 것을 확인한 뒤 기본 예약의 제거 여부를 정하세요. 두 예약을 모두 유지하면 중복 수집될 수 있습니다. 예약 설정 파일을 main에서 변경하면 복구 수집도 한 번 요청됩니다. Vercel 설정은 필요하지 않습니다.

## 4. Vercel 배포

1. https://vercel.com → **Add New → Project → Import Git Repository**에서 이 저장소를 선택합니다.
2. **Framework Preset: Other**, **Root Directory: 저장소 루트**.
3. Build Command는 비워두고, Output Directory는 기본값(루트), Install Command는 `npm ci --omit=dev --ignore-scripts`로 설정합니다.
4. 환경 변수(Environment Variables)에 `DATABASE_URL`만 입력합니다. 비밀번호나 세션 서명 키는 필요하지 않습니다. Production에 적용하고, Preview 환경에서도 사용할 경우 별도로 선택합니다.

| Vercel 변수 이름 | 넣을 값 |
|---|---|
| `DATABASE_URL` | GitHub에 넣은 것과 동일한 Neon 연결 문자열 |


5. Deploy를 누릅니다. 발급된 HTTPS 주소를 열면 기사·대시보드가 바로 표시됩니다. 즐겨찾기는 별표를 누르고, 메모는 기사 상세에서 바로 저장합니다.
6. 기사를 공유할 사람에게 사이트 주소만 전달합니다. 즐겨찾기와 메모는 각자 저장합니다.

환경 변수 변경 후에는 **Deployments → Redeploy**해야 새 값이 적용됩니다. 기존 `ARCHIVE_PASSWORD`와 `SESSION_SECRET` 변수는 더 이상 사용하지 않으므로 삭제해도 됩니다.

네이버 API HUB를 쓰기 위해 네이버 클라우드 서버를 생성할 필요는 없습니다. Vercel/Neon/GitHub Actions/API HUB 비용은 각각 별도이며 무료 플랜 조건과 유료 전환 공지를 확인하세요.

## 화면 사용법

- 왼쪽 주제, 기간, 제목·설명 검색으로 기사와 주요 단어를 필터링합니다.
- 주요 단어를 누르면 해당 단어로 기사 목록을 검색합니다.
- 기사 제목을 누르면 설명문·개인 메모·원문 링크를 볼 수 있습니다. 전문 수집은 하지 않습니다.
- 별표를 누르면 현재 브라우저의 즐겨찾기에 저장합니다. 저장한 기사도 선택 기간이 적용됩니다. 오래된 기사는 전체 기간 필터에서 확인하세요.
- 카테고리·제목/설명 검색은 기사와 키워드에 함께 적용됩니다. 기간 선택은 기사 목록과 급상승에 적용되며 **검색량 많은 키워드**는 별도로 실제 수집 완료 시각 사이의 구간을 사용합니다. 검색 관심도 그래프는 별도로 고정한 5개 그룹의 최근 30일입니다.
- 새로고침은 DB를 다시 읽습니다. 즉시 수집하려면 GitHub Actions의 Run workflow를 사용합니다.

## 분석 기준과 한계

- 기사는 원문 URL을 우선 식별자로 사용합니다. 원문 URL이 없으면 네이버 링크를 사용합니다. URL은 임의로 재작성하지 않습니다.
- 같은 URL 재수집 시 제목·설명을 갱신하고 즐겨찾기·메모는 유지합니다. 여러 검색어·주제 연결을 별도 테이블에 보존합니다. 현재 개인 메모와 즐겨찾기는 DB가 아니라 브라우저에 저장합니다.
- 초기에는 **2026년 10월 26일 00:00(한국 시간)**부터 조회합니다. 이후 겹침 조회도 이 시작일 이전으로 내려가지 않습니다. 대시보드와 분석에서도 시작일 이전의 기사는 제외합니다. 기존에 저장된 이전 기사는 삭제하지 않습니다. 이후 최근 완료 시점부터 48시간 겹쳐 조회하며 기초 검색어당 최대 500개, 확장 검색어당 최대 200개로 제한합니다. 네이버 검색의 범위·조회 제한 때문에 전체 뉴스 수집을 보장하지 않습니다.
- 주제는 수집 검색어 기준입니다. 기사 하나가 여러 주제에 포함될 수 있습니다. AI 내용 분류는 적용하지 않았습니다.
- **검색량 많은 키워드**는 실제 검색량이 아닌 기사 제목 언급 건수입니다. 직전 완료 시각 초과~최근 완료 시각 이하에 게시되고, 최근 완료 시각까지 DB에 처음 저장된 기사를 집계합니다. 정상 완료·일부 완료 실행만 사용하고 실패·실행 중인 작업은 구간 경계에서 제외합니다. 최초 구간은 아카이브 시작일 이상부터 첫 완료 시각까지입니다.
- 이전 구간은 그보다 한 번 앞의 완료 시각~직전 완료 시각입니다. 동일한 카테고리·검색어 조건에서 각 구간의 상위 18개를 비교해 **이전 목록에 없던 단어에만 빨간 박스와 ▲**를 표시합니다. 기존 단어의 순위·건수 증감은 신규 표시와 관계없습니다. 첫 완료만 있어 비교 구간이 없으면 전부 일반 표시합니다. 구간에 기사가 없으면 이전 구간 결과로 대체하지 않습니다.
- 키워드 박스 오른쪽 위에 집계 구간·비교 구간의 한국 시각, 카테고리·분석 기사 수를 표시합니다. 기사 목록의 기간 선택과 독립적이며 최근 5,000건 한도도 적용하지 않습니다. DB에서 구간 전체를 집계하고 한 기사에서 같은 단어는 한 번만 셉니다. 날짜·주제 조건에 인덱스를 활용합니다. 과거 제목 수정이나 주제 연결 변경은 이전 구간을 다시 집계한 결과에 영향을 줄 수 있습니다.
- 기사 목록·상세의 **기사 게시** 시각은 네이버 뉴스 응답의 `pubDate`를 저장한 `published_at`이며, 수집·조회 시각과 구분합니다. 한국 시간과 연도를 포함해 표시합니다.
- 주요 단어는 **제목의 한글/영문 단어를 단순 추출**하고 일부 불용어를 제외한 기사 수입니다. 한국어 형태소 분석·동의어 통합은 적용하지 않았습니다. 조사나 어미가 남을 수 있습니다.
- 급상승은 최근 24시간 언급 기사 비율에서 직전 7일 비율을 뺀 %p입니다. 최근 최소 3건, 최초 수집 8일 이후부터 표시합니다. 필터와 최대 5,000건 분석 한도가 적용됩니다. 수집 누락·검색어 변경은 지표에 영향을 줍니다. 전체 대중 관심도나 사건별 중복 제거 지표가 아닙니다.
- 검색어 트렌드는 같은 요청 내 최대 검색량을 100으로 정규화한 상대 지수입니다. 실제 검색 횟수가 아닙니다. 요청별 결과를 합치지 않고 최신 요청 전체를 보존·표시합니다. 누락된 날짜는 0으로 채우지 않습니다.
- 조회 기간은 현재부터 최근 N×24시간이며 화면 날짜는 한국 시간입니다. API pubDate는 네이버 제공 시각(미제공 기사는 원문 제공 시각)입니다.
- 기사 목록과 급상승 분석은 최신 최대 5,000건입니다. 수집 구간의 키워드는 이 한도와 독립적으로 DB에서 전체를 집계합니다. 초과 시 경고합니다. DB에는 계속 축적되므로 기간을 좁히거나 추후 서버 페이지네이션을 추가할 수 있습니다.
- 수집 기사는 DB에서 자동 삭제하지 않습니다. 트렌드 요청 스냅샷은 90일 보존합니다. DB 백업과 용량 관리는 Neon에서 설정하세요.

## 개인 저장 기준
- 메모와 즐겨찾기는 **현재 사이트 주소의 현재 브라우저**에 저장됩니다. 다른 기기·브라우저·도메인·미리보기 URL에서는 별개의 데이터입니다.
- 새로고침과 일반적인 브라우저 재실행 후에도 유지되지만, 사이트 데이터 삭제·시크릿 창 종료·브라우저 정책에 따라 삭제될 수 있습니다.
- 즐겨찾기 또는 메모가 있는 개인 저장에는 기사 제목·설명·URL·날짜·주제 사본도 보관하므로 최신 5,000건 조회에서 빠진 기사도 **내 저장 기사 → 전체 기간**으로 볼 수 있습니다. 서버 조회에 실패해도 개인 저장 목록은 열 수 있습니다.
- **내 저장 기사**에는 별표를 누른 기사와 메모를 남긴 기사가 함께 표시됩니다. 별표를 해제해도 메모가 남아 있으면 목록에 유지됩니다. 별표와 메모를 모두 지우면 개인 저장 사본도 제거됩니다.
- 메모는 최대 5,000자입니다. 브라우저 저장 공간 부족 또는 저장 차단 시 성공으로 표시하지 않고 오류를 안내합니다.
- 같은 브라우저의 다른 탭에서 수정한 내용도 반영됩니다. 개인 저장 목록에서는 개인 데이터만 보여주며 서버 분석 그래프는 숨깁니다.
- 기존 DB의 공유 메모·즐겨찾기는 삭제하지 않지만 공개 API에서 반환하거나 개인 저장소로 자동 복사하지 않습니다. 이전에 공유로 작성한 내용을 옮겨야 한다면 별도의 수동 이관이 필요합니다.

## 검색 관심도 그래프의 Hot topics
- 선이나 점에 마우스를 올리거나 모바일에서 누르면 선택한 날짜·항목의 관련 기사 제목 키워드를 최대 10개 보여줍니다. 키보드는 그래프에 포커스를 둔 뒤 좌우로 날짜, 위아래로 항목을 선택하고 Escape로 닫습니다.
- 네이버 인기 검색어 순위가 아니라 **저장된 관련 기사 제목의 단어별 언급 기사 수**입니다. 그래프 자체의 상대 검색 지수와는 별도 지표입니다.
- 해당 항목의 비교 검색어가 제목·설명 또는 수집 검색어에 포함된 기사를 한국 시간 날짜 기준으로 조회합니다. 최대 최신 4,000건을 분석하고, 한도를 넘으면 팝업에 범위를 표시합니다.
- 2026년 10월 26일 이전이나 관련 기사가 없는 날짜는 없다고 안내합니다. 10개 미만이면 실제로 있는 만큼만 표시합니다.
- 팝업은 저장된 DB만 읽습니다. 네이버 API 추가 호출은 하지 않으며 같은 날짜·항목 결과를 브라우저 메모리에 5분간 캐시합니다.
